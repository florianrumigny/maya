# Visual foundation studies

Use after territory selection when no approved visual system exists, when the user wants to judge type and color before screens, or when previous probes lacked a recognizable identity. End with 1-2 provisional systems worth testing in a real interface.

Skip this stage when existing brand or product primitives already govern the relevant choices.

## Derive the system

Translate each territory's thesis into one coherent foundation system:

- typography: families, roles, hierarchy, weights, and language coverage;
- color: semantic roles, contrast relationships, and light/dark intent when relevant;
- form: geometry, radii, borders, elevation, density, and spacing rhythm;
- imagery and iconography: subject, framing, treatment, and source strategy;
- material and motion: texture, depth, transitions, and reduced-motion expression;
- signature: one useful, repeatable mechanism identifiable without the logo.

Derive typography and color from the thesis. Test type with realistic language, accents, dates, numbers, short labels, and long content. Test color in functional roles and visible states rather than as swatches alone.

## Compare matched style tiles

Use the same compact content fixture and platform context for every contender. Include enough applied material to expose the system:

- product name and one heading;
- body content and metadata;
- primary action and navigation element;
- image or content object when central to the product;
- active, inactive, and critical state colors.

Show the foundations as a style tile or equivalent board; full-screen composition belongs to the Probe step. When available, Taste `brandkit` may create the board and the platform-specific Taste image generator may render applied UI fragments. Generated output remains a hypothesis.

For each system, name its strongest identity signal, accessibility or localization risk, implementation risk, and likely failure mode. Run the relevant checks from [critic-loop.md](critic-loop.md) when the board will determine the shortlist.

Continue when the user selects 1-2 systems for matched screen probes. Keep values provisional until a system survives a representative real screen; only the approved contract and executable primitives become normative.
